# Монитор объявлений о недвижимости — MVP

## Цель

Личный сервис читает новые и отредактированные сообщения только из заданного
списка Telegram-групп и каналов. Он находит объявления о продаже квартир в
Батуми с планировкой 1+1 или 2+1 и ценой до 75 000 USD, затем отправляет
карточку совпадения в одну закрытую группу получателей.

Сервис не ищет неизвестные чаты, не вступает в группы, не пишет авторам
объявлений и не передаёт тексты внешним AI-сервисам.

## Правило первого запуска

```json
{
  "intent": "sale",
  "propertyTypes": ["apartment"],
  "price": { "currency": "USD", "max": 75000 },
  "cities": ["Batumi", "Батуми"],
  "layouts": ["1+1", "2+1"],
  "exclude": ["rent", "аренда", "daily", "посуточно"]
}
```

В первой версии GEL и EUR не конвертируются автоматически. Варианты `1 + 1`,
`1plus1`, «евродвушка» и соответствующие варианты 2+1 распознаются; обычная
«1-комнатная» не является совпадением.

## Подключение личного аккаунта

1. Создать Telegram application на `my.telegram.org` и получить `api_id` /
   `api_hash`.
2. Локально выполнить `npm run property-monitor:login`, ввести номер, код и
   пароль 2FA.
3. Сохранить выведенную строку только как `TELEGRAM_SESSION` в секретах
   RelaxDev. Не помещать её в Git или мессенджеры.
4. Добавить этот личный аккаунт в группу получателей с правом отправки
   сообщений. Команда `npm run property-monitor:chats` показывает numeric ID
   доступных групп, которые нужно указать в `MONITORED_CHAT_IDS` и
   `NOTIFICATION_CHAT_ID`.

При утечке сессии её следует отозвать в Telegram: «Настройки → Устройства»,
удалить секрет в RelaxDev и повторить вход.

## Архитектура

```text
Allowlisted Telegram chats → MTProto listener → parser/rules → PostgreSQL
                                                            → target Telegram group
```

PostgreSQL хранит только идентификатор сообщения, хеш текста и извлечённые
признаки. Текст сообщения не сохраняется. Уникальность
`(chat_id, message_id, rule_version)` предотвращает повторные уведомления.

`/health` показывает, что процесс жив; `/ready` успешен только после
подключения к PostgreSQL и проверки MTProto-сессии. `INITIAL_BACKFILL_LIMIT`
равный нулю отключает историю; ненулевое значение ограничено 100 сообщениями
на источник.

## Deploy в RelaxDev

Использовать корневой `Dockerfile` с build context корня репозитория. В secrets
перенести обязательные значения из `.env.example`; отдельный PostgreSQL должен
быть доступен по `DATABASE_URL`. Запуск контейнера применяет схему БД перед
стартом listener. Нужна одна реплика, чтобы исключить дублирование updates.
